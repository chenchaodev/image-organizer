# 路线图与迭代规划

> 未来规划:需求范围/迭代/里程碑/已定取舍。只留规划,历史交给 CHANGELOG,「为什么」交给 ADR.md;规划或里程碑变化时更新本文件。

## 需求范围
- 目标:非破坏式本地图片管理器——扫描用户现有目录建索引,图片原地不动;整理动作由软件执行并写回磁盘
- 边界:个人 1万~10万张;跨平台桌面(Win/Mac/Linux)
- 硬需求:本地图片库整理归类、重复图片检测、批处理工具(按优先级排序)

## 功能规划
- MVP(迭代 1-3):M0 骨架(工程+SQLite+目录选择) → M1 扫描浏览(增量扫描+元数据+缩略图+网格浏览) → M2 去重(pHash+相似组+清理)
- 一期不做:标签体系、全文搜索、批处理(重命名/转换/压缩,排 M3)、AI 识别(人脸/场景,选型未定)、云同步

## 迭代规划(每迭代独立交付,每次含验收标准)
- 迭代 1「M0 骨架」✅:Tauri 工程、前端框架、SQLite 初始化、图库目录选择;验收:应用启动、前端↔Rust IPC 通、库文件可创建(2026-08-18 验收通过,明细见 ACCEPTANCE)
- 迭代 2「M1 扫描浏览」🔄:增量扫描器(mtime+size 跳过未变更)、元数据/EXIF 解析、缩略图后台队列、虚拟滚动网格+详情面板;HEIC 支持(libheif-rs,ADR-03);验收:10万张首扫 <10 分钟量级、滚动流畅、重启增量秒级(ACCEPTANCE 待实测清单)
- 迭代 3「M2 去重」:pHash + 分桶相似度、重复组视图、清理动作(移到回收站);验收:样例集去重准确、10万张无 O(n²) 卡死
- 迭代 4「M3 批处理」:批量重命名(模板规则)、格式转换、压缩(延后)
- 迭代 5「M4 完善」:标签、搜索、观看文件夹自动同步、性能优化(延后)

## 延后(不排期)
- AI 识别(人脸/场景/OCR):依赖模型选型(本地 vs API),价值待确认
- 云同步/多端:需求未确认

## 已知限制(技术债/不做,记录不遗忘)
- 去重相似度:粗分桶后桶内细比,桶边界样本可能漏检,待 M2 实测评估是否需跨桶补偿
- 首扫耗时:取决于磁盘与解码速度,目标 <10 分钟量级,超限调并发参数
- 缩略图缓存膨胀:按需生成+分级缓存,后续加清理机制
