## 阅读路径(按场景)

- 新会话/新人上手 → STATUS.md → 本文件(按登记表定位) → 按需查阅
- 搭环境/跑命令/找代码 → DEV-GUIDE.md
- 追溯「为什么这么设计 / 这个库有什么坑」→ RESEARCH.md / ADR.md
- 看进度与计划 → STATUS.md / ROADMAP.md / CHANGELOG.md
- 使用产品 → USER-GUIDE.md
- 交付与实测 → ACCEPTANCE.md

## 文档登记

| 文档 | 用途 | 更新时机 |
|---|---|---|
| `STATUS.md` | 当前状态/打开事项 | 每次收尾 |
| `CHANGELOG.md` | 变更历史(随发版更新) | 发版/迭代完成时 |
| `RESEARCH.md` | 库/技术事实、坑、调研结论 | 收到终态结果/自踩坑确认时 |
| `ADR.md` | 架构决策(ADR) | 做架构决策/审查时 |
| `ROADMAP.md` | 需求范围/规划/里程碑 | 规划变更或里程碑完成时 |
| `DEV-GUIDE.md` | 环境/命令/代码地图/验证基线 | 环境、命令或验证基线变化时 |
| `USER-GUIDE.md` | 终端用户使用说明 | 功能或设置变化时 |
| `ACCEPTANCE.md` | 验收清单与实测记录(按迭代追加,历史明细作回归用例) | 迭代规划/实测完成时 |

其余文档(REQUIREMENTS.md / TEST-MANUAL.md):默认不建,确有需要才建,建文件同批在本表追加一行。故障排查不单独建文档,坑/根因沉淀在 RESEARCH.md。调研/决策分析原文存档于 `docs/archive/` 并在下方「调研存档清单」登记(说明见 `docs/archive/README.md`)。

## 维护约定

- 条目格式遵循全局 AGENTS.md「落盘格式」节(结论/理由/来源/关联)。
- 累积型文件(研究结论/架构决策/CHANGELOG):行数自然增长,不设上限、不做全量审计;新条目在上,同主题更新旧条目并置顶。
- 使用中顺手清理:读到已失效的研究结论 → 删除该条目;读到被推翻的架构决策 → 旧条目首行标「已被 YYYY-MM-DD HH:mm:ss 条目取代」,保留不删。
- 状态速查是每会话入口,保持 ≤80 行:收尾更新时顺手删除已关闭的打开事项与过期状态,超线当场瘦身。
